name: whiteboard
description: Use when Nathan requests /whiteboard or a system-design discussion without implementation.
---

Resolve all paths from the Pennywise repository root (the ancestor containing `learning/`),
not from the caller's working directory. Read `learning/TEACHING.md` before proceeding.

Whiteboard the requested system collaboratively, with no code. For an unspecified system,
use a relevant Pennywise design decision. If a separate system is explicitly requested, honour
it and connect useful lessons back to Pennywise. Read relevant source lessons via the curriculum.
Use RESHADED: requirements, estimation, storage schema, high-level design, API, detailed design,
evaluation and distinctive features. Let Nathan lead; ask one question and wait before advancing.
Use current Pennywise architecture where verified and labelled hypothetical extensions otherwise.
For cloud-related decisions consider the ongoing AWS integration, verifying what exists before
using it as a premise. Discuss managed-service mechanisms and trade-offs, not just service names.
Use sketches when useful. Capture notes after reasoning; no automatic production changes.
